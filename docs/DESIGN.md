# 系統設計文件

本文件描述 Mini 待辦事項的產品與系統設計決策，包含目標、使用情境、功能需求、畫面設計、互動流程、資料設計與邊界條件。技術實作細節請搭配 [系統架構與技術文件](ARCHITECTURE.md) 閱讀。

## 1. 設計目標

### 1.1 主要目標

1. **離線優先**：所有核心功能不需網路即可使用。
2. **低認知負擔**：以清單卡片為核心，讓使用者快速掌握待辦狀態。
3. **多層次待辦**：一個待辦可包含多個清單項目，適合購物清單、旅遊準備、工作拆解等情境。
4. **時間感明確**：以逾期、今天、接下來、無日期分類，降低自行判斷時間的成本。
5. **不打擾**：只有使用者設定的時間才提醒；不包含廣告、追蹤或推播。
6. **資料可攜**：提供 JSON 匯出／匯入，避免資料被鎖在 App 內。
7. **一致外觀**：App 與桌面小工具共用主題與色彩。

### 1.2 非目標

- 不提供雲端同步與多人協作。
- 不提供帳號、社群或分享功能。
- 不提供複雜專案管理（甘特圖、依賴關係、標籤系統）。
- 不提供跨平台版本。
- 不追求秒級小工具更新。
- 不處理跨時區的絕對日期語意（目前以裝置時區儲存）。

## 2. 目標使用者與情境

### 2.1 目標使用者

- 想要一個簡單、離線、無廣告待辦 App 的使用者。
- 需要將待辦拆成多個步驟或購物項目的使用者。
- 希望從桌面小工具快速勾選項目的使用者。
- 重視資料留在本機與開放原始碼授權的使用者。

### 2.2 主要使用情境

| 情境 | 流程 |
| --- | --- |
| 新增購物清單 | 建立待辦「採買」→ 新增多個項目 → 到賣場展開清單逐項勾選 |
| 安排今日工作 | 建立待辦 → 為項目設定開始時間 → 首頁「今天」區段顯示 |
| 追蹤逾期事項 | 項目超過結束時間 → 自動進入「逾期」區段並顯示紅色提示 |
| 快速完成 | 在首頁滑動卡片向右，或直接勾選項目 |
| 封存舊資料 | 向左滑動封存，或從封存頁還原 |
| 桌面快速查看 | 新增小工具 → 選擇待辦 → 直接勾選項目 |
| 時間提醒 | 設定項目開始時間 → 通知提供完成或延後 |
| 換手機 | 匯出 JSON → 在新裝置匯入 |

## 5. 畫面設計

### 5.1 待辦清單（首頁）

**目的**：快速掌握所有待辦與完成進度。

**組成**：

- TopAppBar：標題、搜尋、排序、更多選單。
- 內容：
  - 載入中：置中進度圈。
  - 錯誤：標題與說明。
  - 空狀態：引導新增第一個待辦。
  - 搜尋無結果：提示更換關鍵字。
  - 分類清單：區段標題 + 待辦卡片。
- FAB：新增待辦。

**待辦卡片**：

- 左側顏色條（6dp）。
- 完成核取方塊。
- 標題（完成時加刪除線）。
- 進度（例如 2/5）與最近時間。
- 逾期標籤。
- 展開／收合按鈕。
- 手動排序時的拖曳把手。
- 展開後顯示清單項目，未完成在上、已完成在下。

### 5.2 新增／編輯待辦

**目的**：集中編輯待辦與所有項目。

**順序設計**：

1. 標題
2. 標記待辦完成
3. 顏色
4. 待辦清單

顏色放在完成開關下方，讓「狀態」相關操作相鄰，接著才是視覺標記與內容編輯。

**項目卡片**：

- 拖曳把手、完成核取方塊、「已完成」文字、刪除按鈕。
- 項目標題。
- 開始日期時間。
- 結束日期時間。

**返回行為**：

- 有未儲存變更時顯示「放棄變更？」對話框。
- 儲存中不可返回。
- 使用 `BackHandler` 攔截系統返回鍵。

### 5.3 封存頁

- 空狀態：說明封存的待辦會顯示在此。
- 每筆顯示標題、封存時間、還原與刪除。
- 刪除需二次確認。

### 5.4 設定頁

分為五個區段：

1. 一般
2. 外觀
3. 通知與提醒
4. 備份與還原
5. 關於

排序與主題使用對話框選擇；備份使用系統檔案選擇器；權限項目可直接開啟系統設定。

### 5.5 小工具設定

- 顯示所有未封存待辦。
- 單選清單。
- 尚無待辦時顯示引導文字。
- 讀取既有設定失敗或儲存失敗時顯示 Toast。
- 確定後更新小工具並結束。

## 6. 互動設計

### 6.1 滑動手勢

| 方向 | 動作 | 顏色提示 |
| --- | --- | --- |
| 由左向右 | 切換完成狀態 | Primary container |
| 由右向左 | 封存 | Error container |

滑動不會真正移除卡片，而是觸發動作後回到原位，避免誤刪。

### 6.2 拖曳排序

- 長按拖曳把手後開始拖曳。
- 接近邊緣時自動捲動。
- 拖曳中提高陰影與層級。
- 放開後寫入 `position`。
- TalkBack 使用者可使用「上移／下移」自訂動作。

### 6.3 復原機制

- 刪除清單項目：Snackbar + 復原。
- 封存待辦：Snackbar + 復原。
- 永久刪除：二次確認，不提供復原。

### 6.4 空狀態與錯誤

每個主要畫面都有：

- 載入中。
- 空資料。
- 錯誤。
- 搜尋無結果（首頁）。

### 6.5 無障礙

- 可點擊元件提供 `contentDescription`。
- 核取方塊描述包含動作與項目名稱。
- 拖曳排序提供 TalkBack 自訂動作。
- 滑動操作同時提供核取方塊與更多選單替代路徑。
- 顏色選擇提供文字標籤。
- 觸控目標至少 48dp。

## 7. 核心邏輯設計

### 7.1 分類狀態機

```text
待辦
├─ 已封存 → 不顯示於首頁
├─ 已完成 → 已完成區段
└─ 未完成
   ├─ 有未完成項目逾期 → 逾期
   ├─ 最早開始 < 明天開始 → 今天
   ├─ 有開始時間 → 接下來
   └─ 無開始時間 → 無日期
```

逾期判斷：

- 項目有結束時間：結束時間（全天取當日結束）早於現在。
- 否則有開始時間：開始時間早於今天開始。
- 兩者皆無：不逾期。

### 7.2 完成狀態機

```text
有清單項目：
  所有項目完成 ⇔ 待辦完成
  勾選待辦 → 所有項目完成
  取消待辦 → 所有項目未完成
  勾選／取消單一項目 → 重新計算待辦

無清單項目：
  待辦完成狀態由「標記待辦完成」開關決定
```

### 7.3 排序決策

- 預設「最早開始時間」符合多數人以時間安排待辦的習慣。
- 「建立時間」適合快速查看最新加入的項目。
- 「手動排序」提供完全自訂，但只在「全部」區段套用，避免與時間分類衝突。
- 已完成待辦不使用使用者排序，統一依完成時間由新到舊。

### 7.4 時間設計

- 時間以 epoch millis 儲存。
- 顯示時使用裝置時區。
- 全天事件：
  - 儲存當天午夜。
  - 提醒時間為 09:00。
  - 有效結束為當日結束。
- 日期選擇器使用 UTC 午夜，避免時區造成日期偏移。
- 跨年份時顯示完整日期；同年度顯示省略年份的短日期。

## 8. 提醒流程設計

```text
使用者儲存含時間的項目
  → Repository 寫入
  → notifyChanged(reminders = true)
  → SideEffectCoordinator debounce 400ms
  → ReminderScheduler.rescheduleAll()
      → 取消既有排程
      → 讀取有效項目
      → 排程開始／結束鬧鐘

鬧鐘觸發
  → ReminderReceiver
      → 驗證項目仍存在、未完成、未封存
      → 驗證觸發時間未偏差超過 1 分鐘
      → 顯示通知
          ├─ 點擊 → 開啟待辦
          ├─ 完成 → 標記完成、取消通知
          └─ 延後 → 10 分鐘後再提醒
```

設計理由：

- 集中重排可避免個別新增／刪除造成的排程不一致。
- 400ms debounce 可合併連續編輯。
- 觸發時再次驗證，避免通知已刪除或完成的項目。
- 延後使用獨立 PendingIntent，避免覆蓋原始提醒。

## 9. 小工具設計

### 9.1 設計選擇

- 每個小工具只顯示一個待辦，避免小尺寸空間資訊過載。
- 最多 5 個項目，超出顯示「+N 項」。
- 未完成項目優先，已完成項目在後。
- 直接勾選項目，減少了開啟 App 的步驟。
- 跟隨 App 主題，維持視覺一致。

### 9.2 狀態處理

| 狀態 | 顯示 |
| --- | --- |
| 未選擇 | 「尚未選擇待辦」與重新配置提示 |
| 載入中 | 「載入中…」 |
| 待辦不存在 | 「此待辦已不存在」 |
| 正常 | 待辦標題、顏色、項目、進度 |

### 9.3 更新來源

- 資料變更。
- 主題變更。
- 每日背景工作。
- 使用者重新配置。

## 10. 備份設計

### 10.1 設計原則

- 使用開放格式 JSON，方便檢視與長期保存。
- 包含封存資料，確保完整還原。
- 使用 SAF，不申請儲存權限。
- 匯入前二次確認，因為採覆蓋策略。
- 限制檔案大小，避免異常檔案造成記憶體問題。

### 10.2 匯入流程

```text
選擇檔案
  → 讀取 bytes
  → 檢查大小 <= 5MB
  → 解析 JSON
  → 檢查 version == 1
  → 刪除所有資料
  → 於同一交易寫入所有待辦與項目
  → 重新整理提醒與小工具
```

### 10.3 為何採覆蓋而非合併

- 合併需要處理 ID 衝突、重複資料與時間衝突，複雜度高。
- 覆蓋行為明確，適合備份還原與換機。
- 對話框明確警告，降低誤操作風險。

## 11. 主題設計

- 使用 Material 3 色彩系統。
- 預設跟隨桌布（Android 12+），讓 App 融入系統。
- 提供 6 種固定色盤，讓舊版或偏好固定色彩的使用者有選擇。
- 深色模式支援跟隨系統、強制淺色、強制深色。
- App 與小工具共用色盤解析邏輯。
- 系統列透明並依深色模式調整圖示顏色。

## 12. 隱私與安全設計

- 無網路權限，從技術上避免資料外傳。
- 無帳號、廣告、分析 SDK。
- 關閉 Android 自動備份，避免資料進入雲端備份。
- 備份檔由使用者自行選擇位置，App 不主動分享。
- 不記錄 API Key、密碼或個人識別資訊。
- 簽章金鑰不納入版本控制。

## 13. 邊界條件與處理

| 情境 | 處理 |
| --- | --- |
| 空白標題 | 阻止儲存並提示 |
| 空白清單項目 | 儲存時忽略 |
| 結束早於開始 | 阻止儲存並提示 |
| 待辦無項目 | 使用完成開關 |
| 所有項目完成 | 自動完成待辦 |
| 取消完成 | 清除完成時間 |
| 項目刪除 | 支援 Snackbar 復原 |
| 待辦刪除 | 連同項目 cascade 刪除 |
| 小工具待辦被刪除 | 顯示「此待辦已不存在」 |
| 無精確鬧鐘權限 | 降級非精確排程 |
| 無通知權限 | 不顯示通知 |
| 備份過大 | 拒絕匯入 |
| 備份版本不符 | 拒絕匯入 |
| 匯入失敗 | 保持原資料（交易內刪除後寫入失敗會回滾） |
| 深連結無效 ID | 返回上一頁 |
| 跨時區 | 已知可能日期位移 |

## 14. 設計決策紀錄

| 決策 | 選擇 | 理由 |
| --- | --- | --- |
| 資料儲存 | Room + DataStore | 結構化查詢與 Flow 支援；設定輕量 |
| 狀態管理 | ViewModel + StateFlow | 與 Compose、生命週期整合良好 |
| 事件傳遞 | Channel | 一次性事件不重播 |
| 分類邏輯 | Domain 純函式 | 可測試、與 UI 解耦 |
| 小工具 | Glance | Compose 風格 API，支援 Material 3 |
| 提醒 | AlarmManager | 需要準時觸發，WorkManager 不保證時間 |
| 備份 | JSON + SAF | 開放格式、免儲存權限 |
| 主題 | Material 3 + Dynamic Color | 與系統一致、支援深色 |
| 版本目錄 | Version Catalog | 集中管理相依版本 |

- `versionName` 採 `主.次.修`。
- `versionCode` 每次功能變更遞增。
- `debug`：開發用，附 `-debug`。
- `prerelease`：R8 + Debug 簽章，附 `-prerelease`，用於 GitHub Pre-release 測試。
- `release`：正式簽章，供上架使用。
- 首個 GitHub 公開發行版本為 `1.0.0-prerelease`，明確標示為預覽測試版。
